## Key Architectural Decisions

### Data Model Reconciliation
The existing codebase already had `lib/clients.ts` and `data/clients/aaron-sansoni.json` with a specific schema. Instead of rewriting, I extended:
- Existing deliverables use `status: "delivered"` with a separate `client_reviewed: boolean` flag (not a unified status enum)
- `getDeliverableDisplayStatus()` maps this split pattern to the spec's unified workflow: draft | delivered | client_reviewed | final
- Product matrix uses `match: string` ("Excellent", "Good", "Pending") not `rating`

### Auth Flow
- Auth API (`/api/client/auth`) uses bcrypt against env vars `CLIENT_CODE_{slug}` and `CLIENT_MASTER_CODE` (pre-existing)
- Supports both JSON (API clients) and form-encoded (native HTML form) content types
- Sets httpOnly cookie `client_auth_{slug}` with 30-day expiry
- Pages check cookie existence (simple check, no bcrypt on each page load — future improvement: signed tokens)

### MDX Rendering
- Uses `next-mdx-remote/rsc` (already in dependencies)
- Custom components: `Figure` (image with numbering), `Footnote` (hover tooltips), styled headings, tables
- TOC generated by regex-parsing `##`/`###` headings from raw MDX before rendering
- TOC sidebar uses IntersectionObserver for active section tracking

### Mobile Detection
- Server-side via `headers().get('user-agent')` in layout
- Full-screen overlay with WAG logo for mobile/tablet (no responsive design as per spec)

### Status Update
- "Mark as Reviewed" writes directly to `data/clients/{slug}.json` (filesystem — works for dev/MVP)
- For production on Vercel: replace with DB or blob storage

## URL Structure
```
/client/{slug}                              -> Login / Home
/client/{slug}/{project}                    -> Project Dashboard
/client/{slug}/{project}/reports/{id}       -> Report Detail
/api/client/auth                            -> Auth (POST)
/api/client/feedback                        -> Feedback (POST)
/api/client/status                          -> Status update (POST)
```
